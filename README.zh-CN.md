# pi-purge

[English](README.md) | 中文

[opencode](https://github.com/sst/opencode) **v2** 的系统提示词实验插件：`/purge` 用来切换一个会话到底带哪套系统提示词 —— opencode 自带的、精简过的，或者只发一份人设提示词。

它的用途是提示词工程：同一句请求在「宿主提示词完整 / 精简 / 缺失」三种条件下的行为差异；自己写的指令做回归测试；以及指令遵循、提示词注入鲁棒性这类受控实验。

关掉时什么都不变：不改提示词、不读盘，行为与没装这个插件完全一致。

目标版本是 opencode v2（基于 2.1.4 开发，使用 `@opencode/plugin` 的 Promise 插件 API），不适用于 opencode v1。

## 安装

插件是单个自包含文件 `index.ts`，没有运行时依赖。

**直接放进去**，不需要任何配置。opencode 会加载配置目录下 `plugins/` 里的 `.ts` / `.js` 文件：项目里的 `.opencode/plugins/`，或者全局配置目录里的同名文件夹。

```bash
mkdir -p .opencode/plugins
cp index.ts .opencode/plugins/pi-purge.ts
```

**或者在配置里指向本仓库目录**。用 opencode 配置的 `plugins` 数组，这也是传选项的方式。本地条目必须是包含 `index.ts`（或 `server.ts`）的目录，相对路径按配置文件所在目录解析：

```json
{
  "plugins": [
    { "package": "/path/to/pi-purge", "options": { "source": "/path/to/persona.md", "mode": "strict" } }
  ]
}
```

然后在会话里：

```text
/purge
```

就这一步。插件内自带一段简短示例提示词，装完不必准备任何文件。想换成自己的提示词：

```text
/purge source C:/prompts/my-instructions.md
/purge mode replace
/purge on
```

`/purge source embedded` 切回内置人设。

## 命令

| 命令 | 作用 |
| --- | --- |
| `/purge` | 切换本会话开 / 关 |
| `/purge on` / `off` | 显式开关 |
| `/purge status` | 当前模式、提示词来源、已加载字符数，以及上一轮实际改了什么 |
| `/purge mode append\|replace\|strict` | 切换组合方式（默认 `strict`） |
| `/purge source <路径\|embedded>` | 换提示词文件，或回到内置示例；切换失败会自动回滚 |
| `/purge reload` | 改完外部文件后重新读取 |

## 模式

| 模式 | 实际发给模型的系统提示词 | 适用场景 |
| --- | --- | --- |
| `append` | 你的提示词 + opencode 原提示词（一字不改） | 对照组：基线行为，加一层自己的指令 |
| `replace` | 你的提示词 + 去掉「助手身份句」（`You are an AI agent running in OpenCode, a coding agent harness. …`）的 opencode 提示词，工具说明 / 其余规则 / 项目上下文保留 | 想测量宿主框架措辞的影响，又不想丢工具上下文 |
| `strict` | 你的提示词 + 仅 `Current working directory: …` | 想把人设/指令当成唯一变量隔离出来。这是默认模式 |

`replace` 依赖固定文案、并且要求身份句在行首。opencode 升级改了措辞，或者当前 agent 自带系统提示词（比如内置的 `explore` 子 agent）时，它会原样保留提示词（退化成 `append`），而不是切错位置 —— `/purge status` 会显示 `身份段 未匹配`。`strict` 不做任何匹配，跨 opencode 版本行为一致。

工具定义走请求的工具列表，不依赖系统提示词，所以三种模式下工具都正常可用，包括 `strict`。

## 会话范围与默认值

- 作用范围是**会话**，按会话 ID 隔离。每个会话都从**关闭**开始 —— 新建的会话、重启后再回来的会话、以及子 agent 跑在其中的子会话。重启 opencode 或重载插件一定回到原始提示词。
- 只改 agent 自己发出的模型请求。会话标题、压缩摘要和 `generate` 调用用各自的提示词，不受影响。
- **不写任何文件**：没有状态文件、没有缓存、没有标记。
- 默认提示词是 `index.ts` 里的一小段示例；`/purge source <路径>` 换成自己的文件，`/purge source embedded` 切回来。
- 想让每个会话都从自己的文件起步，设置插件选项 `source`，或者把 `PI_PURGE_SOURCE` 设成绝对路径：

    ```bash
    PI_PURGE_SOURCE=/home/me/persona.md opencode    # macOS / Linux
    set PI_PURGE_SOURCE=C:/prompts/persona.md        # Windows cmd
    $env:PI_PURGE_SOURCE='C:/prompts/persona.md'     # Windows PowerShell
    ```

    它们只提供初始值：仍然要 `/purge on`，每个会话仍然从关闭开始，会话里的 `/purge source <路径>` 也仍然优先。优先级依次是：会话里的 `/purge source`、`source` 选项、`PI_PURGE_SOURCE`、内置示例。`mode` 选项（`strict` | `replace` | `append`）同样用来预设模式。文件不存在时 `/purge on` 会报错，而不是静默回退到内嵌示例。
- 内置文本故意写得很短：发布到包仓库的内容会被扫描滥用性提示词，完整的人设文本过不了扫描；把自己的提示词放在本地用 `/purge source` 引用。
- 默认模式 `strict`。

## 从 pi 版本迁移

本分支已经取代 pi 扩展，不再支持 pi。命令和模式不变，区别是：

- 状态按会话 ID 保存，而不是按进程。
- 没有底栏的 `PURGE ON` 指示，请用 `/purge status`。
- `replace` 只切身份句 —— opencode 的默认提示词里没有内置文档段可切。
- `PI_PURGE_SOURCE` 仍然有效，另外多了 `source` / `mode` 两个插件选项。

## 做实验时的注意点

- `strict` 会一并丢掉项目指令（`AGENTS.md` 等）、skills 列表、其他插件注入的提示词。这正是它能做单变量隔离的原因，也意味着 `strict` 下的结论不能直接和普通会话对比。
- `append` 侵入最小、信号也最弱：宿主提示词后段权重仍然很大，差异可能不明显。
- `replace` 仍会残留宿主文本，而且其他插件可能在本插件之前或之后改写系统提示词。实践上只有 `strict` 能让人设不和别的框架措辞竞争。
- `/purge` 的回复会作为用户侧消息记进会话，但不会触发模型回合。之后的回合能看到它们，这对严格的单变量实验有影响 —— 建议在最后看一次 `/purge status`，而不是每改一次都看。
- 插件加载顺序会影响 `context` 钩子看到的内容。要留结果的话，建议把 `/purge status` 的输出一起记录。

## 开发

```bash
npm test   # 两个套件，跑在一个小型 mock opencode 宿主上，并断言全程没有写任何文件
```

需要 Node 22.19 或更新版本（直接运行 TypeScript）。实现上只注册一个 `context` 会话钩子和一个 `purge` 命令，无其他钩子、无后台任务、无文件写入。
