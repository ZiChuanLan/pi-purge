# pi-purge

[English](README.md) | [中文](README.zh-CN.md) | 日本語

システムプロンプトの実験のための [pi](https://github.com/earendil-works/pi-coding-agent) 拡張機能です。`/purge` は、セッションで使用するシステムプロンプトを切り替えます — pi の標準プロンプト、それを削ったバリアント、またはペルソナプロンプトのみ。

プロンプトエンジニアリング作業を目的としています：ハーネスのプロンプトがある場合・削った場合・ない場合で同じリクエストの挙動がどう変わるかを比較したり、自分の指示のリグレッションテストを行ったり、制御された条件下で指示追従性やプロンプトインジェクションへの耐性を研究したりするためのものです。

オフの状態では何も変わりません — プロンプトの書き換えも、ディスクの読み込みもありません。pi は拡張機能がインストールされていないのとまったく同じように動作します。

## インストール

```bash
FULL:pi install git:github.com/ZiChuanLan/pi-purge@ffafeb9
pi install npm:pi-purge
```

その後、セッション内で次を実行します：

```text
/purge
```

これだけです。短いサンプルプロンプトがパッケージに同梱されているため、インストール直後でも追加のファイルなしで動作します。代わりに自分の指示を使うには：

```text
/purge source C:/prompts/my-instructions.md
/purge mode replace
/purge on
```

`/purge source embedded` で同梱のペルソナに戻ります。

## コマンド

| コマンド | 効果 |
| --- | --- |
| `/purge` | このセッションでオン/オフを切り替えます |
| `/purge on` / `off` | 書き換えを有効化または無効化します |
| `/purge status` | モード、プロンプトのソース、読み込んだサイズ、および直前のターンで実際に何が変更されたかを表示します |
| `/purge mode append\|replace\|strict` | 合成モードを切り替えます（デフォルトは `strict`） |
| `/purge source <path\|embedded>` | プロンプトファイルを変更するか、同梱のサンプルに戻します。切り替えに失敗した場合はロールバックされます |
| `/purge reload` | 編集後に外部プロンプトファイルを再読み込みします |

## モード

| モード | モデルに送信されるシステムプロンプト | 使うべき場面 |
| --- | --- | --- |
| `append` | あなたのプロンプトを、pi のプロンプトの前にそのまま追加します。 | 対照実験をしたい場合：ベースラインの挙動に自分の指示を上乗せしたもの。 |
| `replace` | あなたのプロンプトの後に、組み込みのアシスタントの自己定義の行と同梱ドキュメントのセクションを取り除いた pi のプロンプトが続きます。ツール一覧、ガイドライン、プロジェクトのコンテキストは残ります。 | ツールのコンテキストを失わずに、ハーネスによる枠付けの効果を測定したい場合。 |
| `strict` | あなたのプロンプトと `Current working directory: …` のみ。 | 自分の指示を単一の変数として切り分けたい場合。これがデフォルトです。 |

`replace` は、両方のセクションを完全一致の文言で検出します。pi のアップデートで文言が変わった場合は、誤ったテキストを削るのではなくプロンプトをそのまま残します — その場合 `/purge status` は `身份段 未匹配`（自己定義の行が見つからない）と報告し、挙動は `append` にフォールバックします。`strict` は一切マッチングを行わないため、pi のバージョンにかかわらず同じように動作します。

ツールのスキーマはシステムプロンプトではなく API の `tools` パラメータで渡されるため、`strict` を含むすべてのモードでツールは引き続き動作します。

## セッションのスコープとデフォルト

- スコープはセッションです。すべての `session_start` — 起動、`new`、`resume`、`reload` — は**無効**の状態で始まります。pi を終了すれば、必ず標準の挙動に戻ります。
- ディスクには何も書き込まれません：状態ファイルも、キャッシュも、マーカーもありません。2 つの pi プロセスが互いに影響し合うことはありません。
- デフォルトのプロンプトは、`extensions/pi-purge.ts` に同梱された短いサンプルです。`/purge source <path>` で自分のファイルを指定し、`/purge source embedded` で戻ります。
- 状態を一切書き込まずに、すべてのプロセスを自分のファイルで開始するには、`PI_PURGE_SOURCE` に絶対パスを設定します：

    ```bash
    PI_PURGE_SOURCE=/home/me/persona.md pi          # macOS / Linux
    set PI_PURGE_SOURCE=C:/prompts/persona.md        # Windows cmd
    $env:PI_PURGE_SOURCE='C:/prompts/persona.md'     # Windows PowerShell
    ```

    これは `source` の初期値を与えるだけです：`/purge on` は引き続き必要で、`enabled` はすべての `session_start` で `false` から始まり、セッション内の `/purge source <path>` がこれを上書きします。ファイルが存在しない場合、`/purge on` は同梱のサンプルに黙ってフォールバックするのではなく、エラーを報告します。
- 同梱のテキストは意図的に最小限にしています。公開されるパッケージは不正なプロンプト内容がないかスキャンされるため、完全なカスタムペルソナは公開時に残りません。自分のプロンプトはディスク上に置き、`/purge source` で参照してください。
- デフォルトのモードは `strict` です。

## 0.1.x からのアップグレード

0.2 では `pi-purge.json` の書き込みも読み込みも行わなくなり、プロンプトファイルの自動検出も行わなくなりました — ペルソナは同梱され、モードのデフォルトは `strict` です。

- `<agent dir>/pi-purge.json` を削除してください。今後は無視されます。
- 有効化はセッションごとです：再起動または `/resume` の後は、もう一度 `/purge` を実行してください。
- `append` と `replace` は、必要であれば以前と変わらず使えます。

## 実験に関する注意

- `strict` は、`AGENTS.md` / プロジェクトのコンテキスト、スキル一覧、他の拡張機能が注入したプロンプトテキストも取り除きます。これによりクリーンな単一変数の設定になりますが、同時に `strict` での結果は通常のセッションとは比較できなくなります。
- `append` は最も影響の小さいモードで、通常は最も弱いシグナルになります：ハーネスのプロンプトの後半のセクションが依然として大きな重みを持つため、差は小さくなることがあります。
- `replace` でもハーネスのテキストは残り、この拡張機能の処理後に他の拡張機能が独自のプロンプトセクションを追加することがあります。実際には、ペルソナが他の枠付けと競合しない唯一のモードは `strict` です。
- 拡張機能の読み込み順は、`before_agent_start` が受け取る内容に影響します。保存する結果には、`/purge status` の出力も一緒に記録することをおすすめします。

## 開発

```bash
npm test   # two suites; both run against temporary agent dirs and assert nothing is written
```

この拡張機能は、`before_agent_start` フック 1 つ、`session_start` フック 1 つ、および `/purge` コマンドを登録します。他のフックも、バックグラウンド処理も、ファイルの書き込みもありません。

## クレジット

この仕組みは [YuJunZhiXue/dsh-purge](https://github.com/YuJunZhiXue/dsh-purge) から移植したものです：ハーネスの自己定義の行をかき消すのではなく**取り除く**というアイデア、3 つの合成モード、そして同梱のプロンプトはすべてそのプロジェクトに由来します。作者の要求に従い、ここにクレジットとリンクを記載しています。
